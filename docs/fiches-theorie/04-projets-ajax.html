Projets, relations SQL et AJAX

Comprendre comment l’application retrouve le bon projet et échange sans recharger la page.

Tables, lignes et identifiants

Une table rassemble des lignes de même nature. Dans projects, chaque ligne décrit un projet. Son identifiant id est stable et unique : deux projets peuvent porter le même nom sans être le même projet.

Dans images, project_id rattache chaque image à son projet. C’est une relation « un projet possède plusieurs images ». Une clé étrangère SQL peut empêcher de rattacher une image à un projet absent.

projects.id ← images.project_id → images.id

Lire un projet sûr

Le navigateur transmet un identifiant, mais cela ne prouve pas qu’il existe. PHP vérifie sa forme, puis cherche l’enregistrement avec une requête préparée. S’il est absent, l’application répond « Projet introuvable » avec le statut 404.

Pour renommer, le serveur reçoit le nouvel identifiant et le nom en POST, vérifie CSRF et le nom, puis lance un UPDATE ... WHERE id = :id. Sans le filtre par identifiant, on pourrait modifier plusieurs lignes.

AJAX en quelques mots

AJAX est un échange entre JavaScript et PHP pendant que la page reste ouverte. Ici, api.js prépare l’appel avec $.ajax() ; app.js gère les boutons, l’attente et le message.

Moment jQueryRôle
.done()Traiter la réponse de réussite confirmée par PHP.
.fail()Afficher un refus ou une erreur réseau sans annoncer un succès.
.always()Terminer l’état d’attente, par exemple réactiver le bouton.

PHP garde ses validations même quand l’action vient d’AJAX. Le navigateur n’est pas une frontière de sécurité.

JSON et responsabilités

JSON est un format de données échangé entre PHP et JavaScript. PHP peut répondre avec un objet qui indique success, un message et les données confirmées. JavaScript utilise cette réponse pour actualiser l’écran. Il ne doit annoncer « enregistré » qu’après confirmation du serveur.

Pour un formulaire de fichiers, FormData transporte les fichiers. Pour les valeurs d’un formulaire normal, une sérialisation simple suffit souvent. Chaque action API devrait avoir une fonction ciblée plutôt qu’un gros bloc AJAX dispersé dans l’interface.

Phrase pour l’expliquer

« Les identifiants distinguent les projets. PHP vérifie celui reçu et filtre chaque lecture ou mise à jour par son id. AJAX permet à app.js d’appeler une fonction de api.js ; PHP répond en JSON, et l’interface annonce seulement le résultat confirmé. »
