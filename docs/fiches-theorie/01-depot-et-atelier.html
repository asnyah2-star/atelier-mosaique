Le dépôt et l’atelier local

Comprendre où se trouvent les fichiers, qui les exécute et comment garder l’historique du travail.

Enregistrer, commit, push : trois actions

  • Enregistrer écrit le contenu du fichier sur le disque.
  • Un commit prend un instantané des fichiers choisis dans l’historique Git. Son résumé décrit le changement, par exemple « Prépare la connexion PDO ».
  • Push origin envoie les commits locaux vers le dépôt GitHub.

Un fichier peut être enregistré sans être commité. Un commit peut exister sans avoir encore été poussé. Avant de valider, relis la liste des fichiers et leur aperçu dans GitHub Desktop.

Le chemin du fichier et son adresse web

public\index.php est un chemin sur le disque. http://localhost/atelier-mosaique/public/ est une adresse demandée au serveur. Le serveur interprète PHP puis renvoie le résultat au navigateur.

Dans ce parcours, public/ est l’organisation du point d’entrée dans le dépôt ; elle n’est pas une racine HTTP isolée. Les dossiers src/, config/, database/ et storage/ doivent rester hors de l’accès web direct selon le montage prévu.

Configuration locale et données

  • config.example.php est un modèle partageable.
  • config.local.php contient les réglages de cet ordinateur : il reste local et ne doit pas apparaître dans les changements Git proposés.
  • La base MySQL et les images dans storage/ sont des données de travail ; Git ne les synchronise pas automatiquement.
À retenir : le dépôt contient le code partageable ; la base et les uploads sont ailleurs ; le fichier de configuration locale ne part pas sur GitHub.

Phrase pour l’expliquer

« J’édite le dépôt qui se trouve dans le dossier servi par Wamp. Apache reçoit l’adresse locale, PHP construit la réponse, puis le navigateur l’affiche. Git garde des versions du code, et Push les envoie vers mon dépôt privé. »
